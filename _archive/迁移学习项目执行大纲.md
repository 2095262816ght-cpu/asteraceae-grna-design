## 第 0 步：自有数据盘点（9月3日–9月6日，2~3 天）

动手前先摸清家底，这一步决定后面所有路线选择。

- 整理全部 gRNA 序列 + Hi-TOM 突变率数据，统计总条数、批次数、每批条数；
- 确认每条数据能否回溯基因组坐标（能否取到 30 bp 上下文 + PAM）；
- 批次质控：画各批次效率分布箱线图，确认批次效应大小，做批次内归一化；
- 检查效率值分布是否有区分度（高/中/低效率都要有）。

产出：干净的结构化数据表（序列、坐标、PAM、批次、归一化效率标签）。
决策点：数据量 <100 条 → 主线走 Stacking（第 3 步备选方案）；≥几百条 → 主线走微调。

## 第 1 步：复现论文模型（9月5日–9月9日，与第 0 步部分并行）

注意：**9月5日摘要提交**穿插在本步之前，先按现有方案写好摘要提交，后续再迭代。

- 浏览器下载 DeepSpCas9 补充材料 Table S1（12,832 条训练数据）：https://www.science.org/doi/10.1126/sciadv.aax9249；
- 用 conda 按 README 建环境，跑通 DeepSpCas9（优先用维护较好的封装：R 包 crisprScore 或 Python 包 genet，内置模型权重；原版代码框架太老作为备选）；
- 同时部署 CRISPRon（github.com/RTH-tools/crispron）；
- 复现验证：用论文自带测试集跑预测，对照论文报告的相关系数，确认环境正确。

产出：可运行的预训练模型 + 复现指标记录。
注意：此步目的不是发论文级复现，跑通、指标大致吻合即可，不要陷入环境地狱。

## 第 2 步：迁移可行性验证（9月9日–9月10日，1~2 天，关键决策点）

在投入训练前，先花最小成本回答"迁移有没有戏"。

- 用 DeepSpCas9、CRISPRon 给全部自有 gRNA 打分；
- 与 Hi-TOM 实测效率算 Spearman 相关系数。

决策点：
- ρ > 0.4：迁移基础好，走第 3 步微调；
- ρ 0.2~0.4：微调 + Stacking 两条都试；
- ρ < 0.2：通用规律迁移差，跳第 4 步，且 Stacking 优先于微调。

产出：迁移性评估报告（每个预训练模型的相关系数 + 散点图）。

## 第 3 步：迁移训练（9月10日–9月21日，约 1.5 周）

主线（微调）：
- 加载 DeepSpCas9/CRISPRon 预训练权重；
- 冻结卷积层，只训练全连接层，小学习率；
- 按基因/靶区域分组划分训练测试集，防数据泄漏；
- 如需加强：公开数据加权混合训练（自有数据高权重）。

备选（Stacking，数据少时启用）：
- 多个预训练模型对每条 gRNA 打分作为特征；
- 自有数据训练顶层岭回归/逻辑回归元模型（照 Chen2022 方案）。

产出：迁移后模型 + 测试集 Spearman 相关系数、AUC。

## 第 4 步：效果评估与数据扩充（按需，9月21日–9月27日，最多 1 周）

评估标准（建议提前定死）：测试集 Spearman ρ ≥ 0.5 视为可用；达不到则进入数据扩充。

扩充途径（按优先级）：
- 网上公开数据集：Chen2022 汇总的 16 个数据集（Doench2016/Azimuth、Chari_293T、XuHL60、Achilles/DepMap 等），加权混合再训练；
- 伪标注：预训练模型给橡胶草基因组候选 gRNA 批量打分，伪标注数据预训练 + 真实数据微调；
- 测量噪声扰动：标签在测序误差范围内扰动，小幅合法扩增。

注：原"中期方案：设计成对文库高通量实验"周期以月计，赶不上 10月4日交付，本次赛期内不采用，仅作为报告中的展望。

禁止：改动序列保留标签的"假扩增"；小数据下用 GAN/VAE 生成数据。

## 与原规划相比的优化点

1. 新增第 0 步数据盘点：数据量和质量决定路线，先摸清再动手；
2. 新增第 2 步迁移可行性验证：几小时就能出结论，避免盲目投入微调；
3. 每步设决策点/退出条件：效果不好去哪一步、达到什么标准算过，提前定死；
4. 第 4 步数据扩充明确优先级，并列入两条禁令（假扩增）；
5. 末尾加湿实验闭环验证：模型预测 → 实验证实，这是项目价值的最终体现，也是比赛答辩的亮点。
