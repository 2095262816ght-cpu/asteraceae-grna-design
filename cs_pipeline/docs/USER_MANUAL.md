## 1. 系统架构与双轨矩阵

本系统严格遵循 **[ADR 0004: 生产级全栈架构升级](file:///d:/lifesciencechallenge/cs_pipeline/docs/adr/0004-fullstack-postgres-fastapi-react.md)** 与 **[SPEC-0001](file:///d:/lifesciencechallenge/.scratch/fullstack-postgres-react/spec.md)** 规范，采用现代生物信息平台的主流工程实践，构建了清晰的**双轨（Dual-Track）体系**：

```mermaid
flowchart TD
    subgraph Track1 [主推荐：生产级现代化全栈平台 (React 19 + FastAPI)]
        UI[React 19 + Tailwind CSS + ECharts] -->|REST / JSON| API[FastAPI 异步应用]
        API --> DB[(关系型数据库: PostgreSQL 16 / SQLite)]
        API --> Engine[核心生物物理与形态二分层推断引擎]
    end

    subgraph Track2 [对照轨：经典算法复现基准 (Ground Truth)]
        ST[Streamlit 单体应用 :8501] --> FileDB[Parquet / CSV 文件只读索引]
        ST --> Native[原生 DeepSpCas9 / CRISPRon 推理]
    end
```

| 系统维度 | 生产级全栈主轨 (本手册重点) | 经典基准对照轨 (Ground Truth) |
| :--- | :--- | :--- |
| **前端架构** | **React 19 + TypeScript + Vite + Tailwind CSS** | Streamlit 1.32+ Python 单体脚本 |
| **后端架构** | **FastAPI (ASGI) + Pydantic v2 + 异步并发** | 无独立后端（Streamlit 内部循环驱动） |
| **数据持久化** | **PostgreSQL 16 / SQLite 3 + SQLAlchemy 2.0 ORM** | 磁盘 Parquet / CSV 文件只读检索 |
| **可视化交互** | **Apache ECharts 基因组正负链双轨散点联动** | Altair / Plotly 静态切片图表 |
| **计算模式** | **非阻塞异步任务队列 + 1.5s 智能轮询进度条** | 阻塞式同步计算（等待期间页面冻结） |
| **适用场景** | 高并发实验设计、批量文件排队处理、历史追溯 | 算法单点复现、原始数据分布对账 |

## 2. 极速环境启动指南（1 分钟上手）

### 2.1 方式 A：Windows 双击一键启动（强烈推荐）

1. 在 Windows 资源管理器中打开项目根目录：`D:\lifesciencechallenge\`；
2. 直接双击运行：[`一键启动全栈系统.bat`](file:///d:/lifesciencechallenge/%E4%B8%80%E9%94%AE%E5%90%AF%E5%8A%A8%E5%85%A8%E6%A0%88%E7%B3%BB%E7%BB%9F.bat)；
3. **系统将自动执行以下全套流水线**：
   - 探测系统 Conda Python 解释器（默认定位 `D:\Miniconda\envs\grna-demo\python.exe`）；
   - 自动执行数据库检查并灌入 **49 个 NLR 抗病基因** 与 **19,839 条已验证 gRNA 靶点**；
   - 自动检测并配置前端 Node.js 构建依赖；
   - 并发拉起 FastAPI 异步后端与 Vite 前端热重载开发服务器；
   - **自动在默认浏览器中弹出主界面**（访问 `http://localhost:5173`）。

### 2.2 方式 B：PowerShell 终端启动

打开 PowerShell，切换至项目目录并执行：

```powershell
Set-Location D:\lifesciencechallenge
.\run_fullstack.ps1
```

*可选启动参数*：
- `.\run_fullstack.ps1 -SeedOnly`：仅执行数据库建表与数据灌库后安全退出，不拉起 Web 服务；
- `.\run_fullstack.ps1 -NoBrowser`：启动前后端服务，但不自动在浏览器中打开前端页面。

### 2.3 方式 C：Docker Compose 容器化编排

在支持 Docker 的生产环境或 Linux 服务器中，执行：

```bash
docker-compose up --build -d
```
一键拉起 `db`（PostgreSQL 16 数据库容器）、`backend`（FastAPI Uvicorn 容器）与 `frontend`（Nginx + React 静态编译容器）。

## 3. 核心功能模块操作详解

### 3.1 全局状态与数据库健康看板

位于工作台顶部，呈现系统的运行态势：

1. **数据库引擎状态**：实时显示当前生效的数据库驱动（`sqlite` 或 `postgresql`）；
2. **物理连通性指示器**：每个操作周期通过 `SELECT 1` 物理探测数据库存活状态，以绿灯标示 `HEALTHY`；
3. **数据资产统计**：实时显示已加载的菊科抗病基因总数（49）以及全基因组扫描得到的 gRNA 候选靶点总数（19,839）；
4. **历史抽屉入口**：右上角配备「历史任务与导出中心」抽屉按钮，支持快速唤出侧边面板。

---

### 3.2 模块一：候选 gRNA 检索与多组学决策面板

**应用场景**：针对给定的靶基因，根据切割区域、脱靶风险、GC 含量与综合效率指标，精确筛选最优 gRNA 候选。

```mermaid
flowchart LR
    A[下拉检索 49 个 NLR 基因] --> B[配置外显子/启动子及着丝粒过滤]
    B --> C[调节最低效率分与 GC% 范围]
    C --> D[选择多组学排序策略]
    D --> E[实时展示多组织表达看板与适宜性诊断]
    E --> F[勾选候选行并触发浮动导出栏]
```

#### 操作步骤：
1. **基因即输即搜**：在基因下拉框中输入基因符号或编号（如 `019420`、`023690` 或 `000110`），支持模糊过滤。系统即时响应并刷新该基因的物理坐标（如 `Chr6: 15,234,100 - 15,239,800`）、链向与功能结构域。
2. **功能元件过滤**：
   - **外显子 (Exon)**：用于完全破坏蛋白编码区（基因敲除 Knockout），默认建议开启；
   - **启动子 (Promoter)**：用于调控区修饰或转录干涉（CRISPRi / CRISPRa）。
3. **着丝粒区屏蔽开关 (Centromere Exclusion)**：默认保持开启。自动剔除高度异染色质化且重复序列密集的高风险着丝粒区间，保障切割可及性。
4. **多维度阈值微调**：
   - **最低效率分滑块**：过滤掉预测活性低于阈值的低效靶点；
   - **GC% 范围滑块**：推荐锁定在 `40% ~ 60%`，确保 DNA/RNA 杂交链热力学稳定性。
5. **多组学排序策略**：
   - `组织优先指数（所选组织）降序`：综合考量序列内在效率、脱靶惩罚与目标器官染色质开放度，**湿实验第一推荐**；
   - `纯序列效率分降序`：基于形态二分层 Beta-Binomial 模型的纯内在切割活性排序；
   - `脱靶计数 mis3 升序`：优先推荐潜在脱靶风险最低的保守位点；
   - `GC% 接近 50%`：优先选择碱基均衡的位点。

### 3.3 模块二：基因组双链物理拓扑与交互式靶点分布图（ECharts）

为攻克传统系统“只有表格看不到空间排布”的痛点，本系统引入了 **Apache ECharts 基因组物理双链拓扑图谱**：

```text
  [Sense Strand 5'->3']    ·    ●(高活性)    ·       ●           
  ═══════════════════════════════════════════════════════════════ (基因组物理骨架)
  [Antisense Strand 3'<-5']     ·         ●       ·      ●(高活性)  
  
  【图表与数据表双向交互联动】：
  - 点击图上任意点位 ──> 表格自动滚动并高亮选中该行候选
  - 点击表格任意行 ───> 图上对应散点立即聚焦高亮并弹出详细悬浮窗 (Tooltip)
```

#### 视觉元素规范：
- **X 轴物理坐标**：真实对应基因在染色体上的碱基物理跨度（bp）；
- **正负链轨道分离**：上方轨道展示正链（Sense）识别位点，下方轨道展示负链（Antisense）识别位点；
- **效率热力色彩映射**：
  - 🟢 **翡翠绿 (80~100 分)**：高活性卓越位点；
  - 🔵 **深海蓝 (60~80 分)**：优质可用位点；
  - 🟡 **琥珀黄 (40~60 分)**：中等活性位点；
  - 🔴 **珊瑚红 (<40 分)**：低活性风险位点；
- **双向联动高亮**：
  - 在散点图上点击任意靶点，下方数据表自动高亮该行；
  - 在数据表中选中任意行，图谱即刻聚焦该散点并展示分子详情浮层（包含 Guide ID、序列、精确坐标与效率）。

### 3.4 模块三：单序列 30bp 结构化实时打分与分子解构

**应用场景**：研究人员自行设计了 1 条特定序列，需要在几毫秒内对其进行分子级结构拆解、序列合规性审查并获得活性打分。

#### 1. 30nt 输入规范与强类型约束
Cas9 酶与靶标结合强烈依赖两侧微环境。输入序列必须为 **30 个碱基（A/T/C/G，不区分大小写，无空格）**：

$$\underbrace{\text{A T C G}}_{4\text{nt 5'侧翼}} \;+\; \underbrace{\text{G C T A A G C T A G G C T A G C A T C G}}_{20\text{nt Guide 识别区}} \;+\; \underbrace{\text{T G G}}_{3\text{nt PAM}} \;+\; \underbrace{\text{A T C}}_{3\text{nt 3'侧翼}}$$

> **系统合规校验**：
> - 长度必须严格等于 30 碱基；
> - 第 25~27 位的 PAM 基序必须符合 `NGG` 规则（即第 26、27 位必须为 `G`）。

#### 2. 分子级结构可视化拆解 (Molecular Decomposition Card)
在输入框输入序列时，下方卡片即时动态渲染出**四段彩色分子结构带**：
- **5' 侧翼区（4nt）**：以紫色胶囊标记；
- **Guide 导向区（20nt）**：以蓝色高亮主区域标记；
- **PAM 基序（3nt）**：以橙色特殊警告色标记，并动态标注是否符合 `NGG`；
- **3' 侧翼区（3nt）**：以灰绿色胶囊标记。

#### 3. 提交与即时打分
点击 **「执行单序列打分」**，系统将在 <100ms 内完成特征提取与模型推断，输出：
- **预测效率分 (0~100)**；
- **GC 含量百分比**；
- **退火解链温度 (Tm)**；
- **打分历史入库记录**（自动持久化至数据库，供后续调取）。

### 3.5 模块四：高通量文件批量上传与异步打分流水线

**应用场景**：面对上百乃至上千条自定义 gRNA 序列，一次性上传文件进行非阻塞排队推理。

#### 1. 标准模板一键下载
点击卡片内的 **「下载 CSV 输入模板」** 按钮，系统将通过接口 `GET /api/v1/scoring/template` 即刻返回标准格式文件：
```csv
sequence,label
ATCGGCTAAGCTAGGCTAGCATCGTGGATC,Sample_Target_1
CCATGCTAAGCTAGGCTAGCATCGTGGAAA,Sample_Target_2
```

#### 2. 拖拽式上传与异步流水线 (Async Pipeline)
- 将本地 `.csv` 或 `.txt` 文件直接拖拽至虚线上传区；
- 系统立即发起异步任务 `POST /api/v1/scoring/upload`，生成全局唯一任务 ID；
- 界面弹出**现代化动画进度条**，利用 TanStack Query 以 **1.5s 智能轮询** 持续跟踪后台进度：
  - 动态显示：已完成百分比、处理中条数、成功数与异常拦截数；
  - **非阻塞设计**：页面无需刷新或冻结，用户可自由切换至其他模块操作；
- 处理完毕后，当前卡片底部自动展开结构化结果明细表，并支持一键导出结果。

### 3.6 模块五：历史任务管理与批量导出中心（侧边抽屉）

点击界面右上角 **「历史任务」** 按钮，侧边抽屉（History Drawer）平滑滑出，提供两大数据面板：

#### Tab 1：打分任务历史 (Scoring Jobs)
- 集中陈列所有单序列与批量上传任务；
- 展示任务提交时间、序列总数、当前状态（`PENDING` / `PROCESSING` / `COMPLETED` / `FAILED`）；
- 支持点击查看历史任务详情，或一键调取历史预测结果。

#### Tab 2：导出批次归档 (Export Batches)
- 当用户在候选列表（模块一）中勾选了多条 gRNA 时，底部浮现 **批量操作工具栏**；
- 点击 **「创建导出批次」**，系统自动将所选靶点固化为一个导出批次存入数据库；
- 在导出中心中，所有批次清晰可查，支持随时点击 **「下载 CSV」**，下载经由 `UTF-8 with BOM` 编码的国际化通用数据表（Excel 打开 100% 无乱码）。

## 5. 常见问题排查与专家建议 (FAQ)

### Q1：双击运行 `一键启动全栈系统.bat` 出现闪退怎么办？
- **原因排查**：检查当前目录路径是否含有非法的特殊转义字符，或本机 Node.js 是否尚未加入系统环境变量。
- **排错方法**：在项目根目录按住 `Shift + 鼠标右键` 选择「在此处打开 PowerShell 窗口」，手动执行：
  ```powershell
  .\run_fullstack.ps1
  ```
  终端将打印详细的每一步排查日志，如有缺失依赖会直接定位具体报错。

### Q2：单序列打分提示“PAM 基序无效：必须为 NGG”？
- **科学原理**：SpCas9 酶切机制必须在靶点 3' 端识别连续的两个鸟嘌呤（GG）。
- **核对要点**：输入的 30bp 序列中，**第 26 位和第 27 位必须均为字母 G**。若目标位点位于基因组反义链（负链），请先将其转换为反向互补链再截取 30nt 输入。

### Q3：为什么预测效率分不等于实验中实测的 Indel 突变率？
- **生物学口径界定**：实际突变率强烈依赖于外植体分化生理状态、农杆菌侵染效价及组织培养温度，跨批次波动极大。
- **系统建议**：本模型推断的效率分属于**脱离实验批次扰动的纯内在活性量度**，主要用于相对优劣排序。建议在同一靶基因的候选列表中，优先挑选 **效率分排名 Top 3~5 且脱靶评分最低** 的序列并行合成质粒，以最大化实验成功率。

### Q4：如何将数据库从 SQLite 切换为生产级 PostgreSQL？
- 在项目根目录的 `.env` 文件或环境变量中配置：
  ```env
  DATABASE_URL=postgresql+asyncpg://postgres:password@localhost:5432/lifescience
  ```
- 重新运行 `run_fullstack.ps1`，系统会自动在 PostgreSQL 中初始化建表并执行灌库。
