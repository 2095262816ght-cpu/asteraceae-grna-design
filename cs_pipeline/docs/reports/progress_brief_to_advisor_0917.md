# 项目进展小汇报（2026-09-17）

> 面向老师的一周进展简报：数据更正、模型现状与定位调整、公开数据检索结论、下一步计划。

## 一句话现状

自有实测数据量小（23 条 guide / 14 个基因，已是该物种最大效率集），**精确预测效率做不到**，已把工具定位从"效率预测"调整为"**候选 gRNA 排序推荐**"（计算筛到每基因 top 几条、实验终筛），交付物（扫描+脱靶+demo）全部可用。

## 一、这几天做了什么

1. **数据表系统性纠错**：对 491 行 Hi-TOM 记录做了全量基因组比对核查，发现并修复 7 类记录错误——221 行链向整列填反、LG01.6995/6999 窗口记偏 5bp、USR-5712 批 guide 张冠李戴、LG07.3296 坐标偏 1bp、LG02.4820 四行 PAM 错记（CCA→实测 ACT）、USR-5712 批 indel 因参考序列方向问题被系统性低估（中位数 0.01→实为 1.0）。每处更正都有基因组序列或原始测序 reads 双重证据，改正前后均有备份可回滚（详见 `docs/problem.md` / `docs/problem2.md`）。
2. **全量重跑训练管线**：以更正后数据重训模型，训练集从 260 行/7 基因扩到 487 行/14 基因，模型泛化指标（留一基因交叉验证 Spearman ρ）从 **-0.23 提升到 +0.41**。
3. **demo 重打分与交付收尾**：19,839 条候选 gRNA 全部改用真实双模型重新打分（此前推理用的是近似公式，已修正）；补齐模型说明书（model card）、更新 README 项目概述、demo 界面与文档统一改为"排序推荐"口径；冻结 `v2.0-freeze` 版本。
4. **公开数据穷尽性检索与两轮混合试验**：系统检索并实测了人源（2.4 万条）、番茄原生质体（420 条）、本氏烟（52 条）公开效率数据，尝试混入训练。

## 二、遇到的问题与解决

| 问题 | 怎么解决的 |
|---|---|
| 数据表错误多（上表 7 类） | 23 条 guide 逐条回基因组比对 + 原始 reads 复算，逐条定案更正 |
| 旧模型指标为负（不可用于供分） | 数据更正后全量重跑，ρ 由 -0.23 → +0.41（达标线 0.5 未达，如实记录） |
| 人源公开数据混合训练 | 50:1~5000:1 权重扫描均不超自有模型，**无效**，放弃 |
| 植物公开数据（番茄/本氏烟）混合 | 同样无增量；但发现**迁移可行性是数据集特异的**（见下） |
| 同科/同种数据 | 公开渠道已穷尽：橡胶草公开 guide 仅 ~10 条且无效率标签，菊科合计可抠 20–30 条但口径混杂——**没有可用的** |
| 环境故障 | scipy 库崩溃（降级修复）、CRISPRon WSL 路径过时（修复）、demo 依赖冲突（拆双环境） |

## 三、一个有价值的附带发现

同两个人源预训练模型，在不同植物体系表现截然不同——**本氏烟上 ρ≈0.85（迁移良好）、番茄上 ρ≈0.03（完全失效）、橡胶草上部分有效**。"跨体系迁移是数据集特异的"这一结论有两个独立植物数据集背书，与近两年文献互相印证，可作为报告的一个科学点（`results/transferability_0917.md`）。

## 四、为什么改为"排序工具"定位

- 23 条 distinct guide（8/14 个基因只有 1 条）撑不起绝对效率预测，ρ=0.41 离 0.5 达标线有距离；
- 但排序能力显著优于随机：**同一基因内按分数取 top 3–5 条送实验，大概率包含可用 guide**——这正是育种筛选的实际用法；
- 因此工具口径统一为：计算负责把 1,387 万候选筛到每基因个位数，实验做最后一公里。所有文档与 demo 界面已按此改写，数字全部如实标注。
