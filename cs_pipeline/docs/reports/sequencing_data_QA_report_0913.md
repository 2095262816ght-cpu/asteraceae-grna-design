## 三、已修复问题详情

### 3.1 "LG02.3008"（35 行）→ LG01.8265

**证据链：**
1. 公司原始文件（`all-SY13249-USR-25902-Hi-TOM-sequencing-result.xls`）中该批全部 35 个靶点 ref 名为 `001~034, 048-ref18265gene1`，即 LG01.8265；同批 `ref73933gene2`=LG07.3933、`ref24820gene4`=LG02.4820 均与表内标注一致，唯独此批错标
2. 参考序列中直接包含靶点序列 `CCAATCGCGAGAAAAAAAAG`+PAM `TGG`
3. indel 数值精确对应：ref 001 的非 WT reads 占比 42.26%+3.43%+1.56%=47.25%，与表内 TKS_0216 的 0.4725 一致
4. 该序列在 TKS 基因组正向命中 LG01:191185778，后接 TGG（合法 PAM），位于 LG01.8265 基因区内；同批次另 1 行（TKS_0177）已正确标注为 LG01.8265

**修复：** gene-id → evm.model.LG01.8265，chrom → LG01，坐标 191185778–191185798，备注注明原标错。

### 3.2 "LG07.262"（61 行）→ LG07.3296，序列翻正

**证据链：**
1. 该批 PAM 全部为 CCA（非 NGG）。CCA 恰为 TGG 的反向互补（TGG→ACC→倒读→CCA），提示序列整体被记录为反向互补
2. 将 `TATATGTTTTCAATATTTTC` 翻正为 `GAAAATATTGAAAACATATA` 后，正向命中 LG07:109029054，后接 TGG（合法 PAM），位于 **LG07.3296** 基因区内（-链基因，靶点在其反义链上）
3. Sheet2 中 LG07.3296 名下本就登记有这条翻正序列（偏移 827），即正确答案早已存在，61 行主表数据引用了错误的序列方向
4. 该批（USR-5712）编辑率全部接近 0%，与"guide 序列记反、实际可能未正确设计"的推断吻合

**修复：** gene-id → evm.model.LG07.3296，seq-20 翻正，PAM CCA→TGG，坐标 109029054–109029074，备注注明。

### 3.3 "LG02.6246"（3 行）→ LG01.6995/6999

**证据链：**
1. 两条 guide（`CGTAAGGATTGCTGCTGAGA`、`TGTTCATCGGTGATCTCGAT`）在 LG02 上均无命中（正向+镜像）
2. 镜像搜索均命中 LG01 的 **LG01.6995**（165462914、165462948）与 **LG01.6999**（165502832、165502866）两个基因，且带合法 PAM AGG——即这两条 guide 实际靶向的是 6995/6999 这对相邻重复基因
3. 这同时解释了 Sheet1 中 6995/6999 交替块与"LG02.6246"三行的关系：它们靶向的是同一基因区域

**修复：** gene-id → evm.model.LG01.6995（暂记，guide 同时打两个拷贝，见待确认项），chrom → LG01，坐标按两条 guide 分别填 165462914–165462934 / 165462948–165462968，备注注明双拷贝情况。

## 五、待老师确认的问题

1. **LG01.6995/6999 的主 guide（`GGATTGCTGCTGAGAAGGCC`+TGG，32 行）在基因组无合法 PAM**：真实位点（LG01:165462909/165502827，-链）后接的是 ATG 而非 TGG。该序列如按表内记录的设计，Cas9 应无法识别。而其旁边 4bp 的另一条 guide（`CGTAAGGATTGCTGCTGAGA`+AGG）是合法的。**需确认：这条 guide 的设计/记录是否挪动了碱基？** 此批恰是编辑率 100% 扎堆的区域
2. **LG02.4820 的 4 行（`AACATGGTTCGAGTTCAAGA`+CCA）同样无合法 PAM**（真实位点处为 ACT）。基因与坐标本身正确，仅 PAM 不成立
3. **60 行编辑率 = 100%**：集中在 USR-8145 批（LG04.2802 连续 17 行、LG01.6995/6999 计 29 行）、LG01.555（4 行）、LG07.3933（8 行）。数值呈"开关式"分布（1.0 / ~0.5 / ~0.1），不像真实编辑效率的连续分布，疑与测序深度、混样或质控有关，需确认是真实值还是数据问题
4. **原"LG02.6246"三行样本（USR-4445/4453/4455）的归属**：guide 同时靶向 6995/6999 两个拷贝，修复版暂记 6995 并已备注，请确认记法
5. **USR-5712 批（原"LG07.262"）编辑率全为 0**：与序列记反的推断一致，需回查当时送测合成的 oligo 序列到底是哪条方向
6. **零散项**：TKS_0160 的 indel_pct 缺失；1 行批次 USR-8146 疑似 USR-8145 笔误；rep 列全表"暂不填"（若做生物学重复分析需补）；efficiency-norm 列空
7. **批次口径**：同学整理时将单样本号（USR-4412~4455、23710~23777 等）并入所属测序订单号，批次口径已统一，但"每行对应哪个植株样本"的信息随之丢失——如后续需要按样本回溯，需对照旧版文件
