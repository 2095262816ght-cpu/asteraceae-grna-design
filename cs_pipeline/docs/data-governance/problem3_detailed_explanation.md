## 2. 核心定调：为什么是“要资料，非判断题”？

在常规数据治理中，如果遇到信息缺失，算法工程师常习惯将问题转化为选择题向业务方或指导教师提问（例如：“老师，这个样本您看选 A guide 还是选 B guide？”）。但在该机器学习管线中，文档特别强调：**这是一个纯粹的“索取客观事实依据”的任务，绝对不能当作主观判断题去“猜”或“拍脑袋决定”。**

### 2.1 470 行数据依靠算法反推的现状
新合并的数据表（877 行新批次）中，虽然有 407 行通过与历史已知扩增子的重合比对锁定了 guide，但剩下的 **470 行**（覆盖 `ref22B18`、`ref05nB5`、`refCALB1` 等 8 个以上扩增子）由于本地仓库中缺失设计台账，目前的 20nt 序列完全是程序**根据测序 reads 突变密集区与 Cas9 几何切割规则逆向反推出来的候选序列**。

### 2.2 算法反推的物理局限（为什么不能盲信算法推测？）
* **突变窗口漂移与大片段缺失**：Cas9 切割后引发的非同源末端连接（NHEJ）修复并不局限于切点（PAM 上游 3bp）正负 1bp 内，很多样本会出现向上游深度延伸超过 10bp 的大缺失。
* **相近 PAM 引起的几何混淆**：在一个 150~250bp 的扩增子中，如果局部紧邻存在两个相距 10~20bp 的 NGG PAM，当发生大范围缺失时，两者的突变频率在序列几何空间上严重重叠。计算机算法仅凭 reads 自身的分布无法 100% 确定到底切的是哪一个位点（历史批次 USR-25902 中的 `ref73933gene2` 已经证实算法反推出现过错误）。

### 2.3 特征错配是监督学习的致命毒药
对于 Stacking 预测模型而言：
* **输入特征 $X$**：来自于 20nt guide 序列本身（包括单/双核苷酸组成、DeepSpCas9 与 CRISPRon 工具打分等）；
* **输出标签 $y$**：是样本块测出的真实编辑效率 `indel_pct`。

如果依靠人工或算法“瞎猜”指定 guide，一旦猜错，就属于**系统性的特征与标签错配（$X \leftrightarrow y$ 挂错）**。模型会被迫去学习“序列 A 能够产生高效编辑”的伪规律，直接破坏梯度方向。因此，**真实做实验合成的 gRNA 序列在物理上是客观且唯一的，必须向实验团队索要原始合成/设计档案，杜绝主观判断。**

## 3. 资料定位：最可能的文件形态与搜寻路径

在生物实验室日常科研流程中，该类信息保存的形式具有明确的**优先级梯度**：

```
【第一优先级：最强物理铁证】
oligo / gRNA 商业公司合成订单（Excel 清单 / 订购发票）
       │
       ▼
【第二优先级：次高置信度】
高通量测序送测单 / 实验 Protocol（送测批次登记表）
       │
       ▼
【第三优先级：人工记录兜底】
设计同学的个人电子记录 / 实验记录本（Benchling / CRISPR-P / 聊天记录）
```

### 1. oligo/gRNA 商业合成订单（最优先）
* **来源**：课题组向金斯瑞（GenScript）、生工生物（Sangon）、擎科（Tsingke）或睿博等生物公司下达的引物/gRNA 合成订单。
* **特征**：通常为 `.xls` 或 `.xlsx` 文件，表内白纸黑字明确标有靶点名称（如 `22B18`、`CALB1`、`05nB5` 等）及其对应的 20nt Oligo 序列（$5' \to 3'$）。该记录具有法律和财务凭据性质，真实度与置信度最高。

### 2. 测序送测单 / 实验方案（次优先）
* **来源**：实验人员将带有不同接头和 Barcode 的 PCR 扩增产物寄送给测序公司做 Hi-TOM 测序时，附带填写的送样登记表。
* **特征**：表格会逐列对应每个板孔/样品编号（如 001-ref22B18）对应的基因名称、扩增产物长度及对应的 gRNA 靶点设计。

### 3. 设计同学的个人记录（兜底）
* **来源**：当年负责设计这一批 gRNA 的研究生本地留存的文档、实验记录本、或者在在线设计工具（如 Benchling、CRISPR-P、CRISPR-GE）中导出的靶点规划表。

## 4. 工程逻辑：为什么拿到后确认是“机械操作（< 1小时完成）”？

文档指出“拿到后确认是机械操作，预计 < 1 小时完成”，其底层技术原因如下：

1. **扩增子已知且唯一锚定**：  
   管线中已经用高通量 reads 拼接出了所有 `ref` 的完整扩增子序列（保存在 `scripts/dev/amplicons.json`），并且全部在 TKS 参考基因组上找到了唯一的物理坐标（染色体及起止位置）。
2. **文本精准包含查找（子串对齐）**：  
   扩增子序列全长通常仅为 150~250bp。拿到设计表里的 20nt 序列后，只需写一段简短脚本：
   * 在正链扩增子中查找该 20nt，若命中，检查其 3' 紧跟的 3bp 是否满足 PAM 规则（`NGG`）；
   * 若未命中，取其反向互补（Reverse Complement）在负链查找，确认 PAM。
3. **`guide候选` 表反向比对秒级校验**：  
   在已生成的整理表 `1_Hi-results-13-NEWdata-20260918.xlsx` 中，专门包含了一个 **`guide候选`** 工作表，为每个 ref 预先计算并保存了 Top-1、Top-2、Top-3 的推荐 guide、基因组坐标以及编辑热点得分。拿到真实设计序列后，只要与现有的候选池进行匹配校验，绝大多数都会直接命中候选表的第一位，几分钟即可完成全量映射与数据表更新。

## 5. 连带判断题 1 深度拆解：ref22B1 与 ref22B23 到底是一条还是两条 guide？

* **问题原文**：`ref22B1 与 ref22B23 的 top1 候选是同一条 guide（LG05:89620961-89620981）——它俩到底是一条还是两条 guide？`

### 5.1 序列与生物信息学实证
在参考基因组与拼接序列（`scripts/dev/amplicons.json`）中比对两个扩增子发现：
* 它们均位于同一个基因 **`EVM.MODEL.LG05.1856`** 上；
* `ref22B1` 主要是偏上游的扩增片段；
* `ref22B23` 是偏下游的扩增片段；
* **两者在基因组上存在近 100bp 的物理重叠**（`ref22B1` 的 3' 端序列与 `ref22B23` 的 5' 端序列完全一致）。
* 关键冲突：在这段重叠区间内，恰好存在一个高活性的 Cas9 切割靶点（序列为 `ATTGATCGGCCGACCATGGT` + PAM `GGG`，坐标为 LG05:89620961-89620981）。这导致算法提取变异峰时，`ref22B1` 批次与 `ref22B23` 批次算出来的**第 1 候选 guide 序列和坐标一模一样**。

### 5.2 需要实验老师裁决的两种可能性

| 业务可能性 | 实验场景解释 | 数据处理应对 |
|---|---|---|
| **可能性 A<br>（同一条 guide）** | 实验设计时其实**只设计了一条 guide**，但为了保证 PCR 扩增成功率，设计了两对不同的引物（22B1 和 22B23）去扩增同一个靶位点。 | 在数据表中，22B1 和 22B23 应该被赋予**同一个 guide-id**，作为同一条 guide 在不同引物/批次下的重复测定。 |
| **可能性 B<br>（两条不同 guide）** | 实验设计时原本在该区域**设计了两条不同且紧邻的 guide**（例如 22B1 测该位点，22B23 测下游另一位点），但因 22B23 的实际 guide 编辑活性弱，算法被重叠区域的假变异带偏，挑错了候选。 | 必须依据设计表把 22B23 的 guide 修正为真正设计的那条，二者使用**不同的 guide-id**。 |

## 6. 连带判断题 2 深度拆解：refsm1 与 refABC49261 双活性切点如何记？

* **问题原文**：`refsm1 / refABC49261 扩增子内有两个活性切点（疑似双 guide 设计）——主表既往只记一条，这批同口径记一条还是记两条？`

### 6.1 现象观察与生物学机理
在扩增子 `refsm1`（对应基因 LG05.2725）和 `refABC49261`（对应基因 LG05.2111）的测序 reads 中，明确观察到了**两个在空间上分离的高频突变峰（切割热点）**，且两个热点附近均严格符合 Cas9 的 NGG PAM 几何特征。
* **生物学解释**：这高度提示该实验采用了 **“双 gRNA（Dual-guide）协同敲除”** 策略——即构建载体时同时转入了两条 gRNA，一条切上游，一条切下游，通过协同切割直接将两个切点中间的 DNA 片段整体切除，达到高效敲除的目的。

### 6.2 机器学习建模与数据治理的深层矛盾

```
           切点 1 (Guide-A)                 切点 2 (Guide-B)
           突变热点 A                       突变热点 B
───────────────▼────────────────────────────────▼───────────────
                     整个样本块实测编辑率: Y%
```

1. **历史主表的做法**：主表的数据结构是“一行数据 = 一个样本块”，且每行仅有单列 `seq-20`。历史整理时**只登记了其中一条主要 guide**（例如 `refsm1` 只记了 `GGCGTTAGATTGACAGAAGA`，`refABC49261` 只记了 `GCGATTCTAAATCTCCCTCA`）。
2. **AI 模型视角下的冲突**：
   * 测序得到的编辑效率 $y$（`indel_pct`）是**两条 guide 共同切割的协同贡献**；
   * **若按历史口径只记一条**：模型在学习时，会把两个 guide 协同产生的高编辑率全部归功于登记的那一条 guide，导致该序列的预测特征被高估；
   * **若强行拆成两条记录**：将同一个测序块复制成两行（一行挂 Guide-A，一行挂 Guide-B，均赋予效率 $y$），会导致同一个编辑率被重复使用两次，违背独立样本假设。

### 6.3 需要老师确认的事项
* 确认这两个扩增子是否确实属于双 gRNA 协同敲除实验；
* 确认新整理的数据表是**“维持历史主表既往口径（仅保留一条主 guide 序列以维持格式兼容）”**，还是**“需要将双切点拆分标注或在特征中单独标识”**。
