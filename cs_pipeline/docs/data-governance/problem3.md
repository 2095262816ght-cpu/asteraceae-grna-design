## 2. 整理产出

**`data/1_Hi-results-13-NEWdata-20260918.xlsx`**，与主表完全同构（列名/列序/口径一致），**877 行 / 17 批次**，guide-id 续主表编号 TKS_0492–1368。三个工作表：

| 工作表 | 内容 |
|---|---|
| `Sheet1` | 主表格式数据（每行 = 一个样本块） |
| `guide候选` | 每个 ref 的 Top-3 候选 guide（基因组坐标 + 热点得分），供对照设计表确认 |
| `说明` | 全部口径记录 |

**整理口径**（均经旧批次校准）：

- **indel_pct** = 1 − 主型 reads 占比 −（主型非 WT 时的 WT 残留）。该规则从 USR-25902 反推出、能复现团队既有口径（含"大片段缺失主型视为材料基线""无 WT 行"的处理）；逐块复算 36/49 与主表完全一致，其余差异系主表当年的手工整理痕迹，不可机械复现。
- **基因/坐标**：全部 ref 的扩增子在 TKS 基因组上唯一命中，gene-id 由 GFF 注释确定；877 行坐标与基因组逐行复核一致。
- **strand** = 原型链在基因组上的方向（已核实主表 491 行均为此口径，不是基因链向）。

**质检（`scripts/dev/validate_newtable.py`）全部通过**：结构一致、guide-id 唯一、seq-20/PAM 全合法且与基因组一致、无重复、17 个批次块数与原始文件逐批对账一致。生成脚本：`scripts/dev/build_newdata_table.py`。

## 3. 核心实验：合并训练为什么不升反降

### 3.1 实验设置

合并表 `data/1_Hi-results-13-merged-20260918.xlsx`（491 旧 + 877 新 = 1368 行），全链路重跑（seq30 重建 → DeepSpCas9 / CRISPRon 打分 → Stacking 训练）。唯一可比的指标是 **LOGO-CV 中位 rho**（留一基因交叉验证，用全量数据）；测试集 rho/AUC 因分组打乱后测试集基因不同，不可比。

### 3.2 结果总表

| 方案 | 数据 | LOGO-CV 中位 rho |
|---|---|---|
| 纯旧数据基线 | 487 行 | **0.414** |
| 全量合并（未做任何处理） | 813 行 | -0.257 |
| 只加 guide 已确认的行 | 544 行 | 0.220 |
| QC 剔除后，raw 标签 | 1014 行 | -0.220 |
| QC 剔除后，批内 z-score | 1014 行 | -0.163 |
| QC 剔除后，批内 rank | 1014 行 | -0.116 |
| QC 剔除后，**锚定校正** | 1014 行 | **+0.280**（test rho +0.145，AUC 0.514） |

注：QC 后四行为 2026-09-18 复检修正 guide 归属（见 3.5）后的重跑结果；raw 的中位数对折构成敏感（3.4），锚定校正数值稳定。

另有关键对照：纯旧数据用批内归一化 → raw 0.388 / z-score -0.077 / rank -0.129。

### 3.3 结果解读（三层问题的分离与证据)

**① 批内 z-score / rank 路线否决**：批次×guide 严重混淆——USR-5713、5712、29107 等 5 个批次只测了 1 条 guide，批内归一化把这些批次的标签直接变成"同一 guide 重复样本间的噪声"，147/487 行旧数据因此被毁。对照实验证明归一化本身有害，与新数据无关。

**② 批次效应是真实存在的大头**：锚定校正（19 条跨批次共享 guide 算各批次中位偏移再减掉，22/24 批次可校正）把 LOGO 从 -0.03 拉到 +0.27、test rho 转正。提升幅度本身就是批次截距存在的证据（例如 USR-14333 被算出整体偏移 +0.85，实锤虚高）。

**③ 但锚定后仍低于纯旧数据基线**（0.280 < 0.414）——剩余差距指向 guide 未确认（下节）和新批次残余质量问题。

### 3.4 一个评测陷阱（留档）

`indel_pct × 100` 的浮点尾差会让"常数折"判定翻转（`32.0` vs `31.999999999999996`），导致 LOGO 折的纳入/排除不稳定、中位数跳动 ±0.3。最终版已统一 `round(6)` 固定（`scripts/dev/m13_final_compare.py`）。文中所有数字均为修正后的稳定值。

### 3.5 复检查发现并修复的整理缺陷（留档）

复检时发现 USR-4811 批次 reads 比其他批次短一截，其 refABCM1 扩增子缺 5' 端 41bp（恰好含 guide 区），导致 87 行的 guide 未能按已确立记录赋值。修复：reads 合并改为双向（允许向前补前缀）+ 已确立 guide 的判定增加坐标包含兜底（容忍样本 SNP）。修复后确定 guide 行数 305 → **407**（8 个 ref 全部落实：refsm1/refABCM1/refABC49261/refSP3/refP2/refABC23135/refSN2/refsn2），候选 470 行，全部下游产物（merged 表、双模型打分、训练对比）已同步重跑。

## 4. 问题分层解析：各是什么、各靠什么解

这三层问题互相独立，必须分开处理——这也是"确认了设计表是不是就够了"的答案：**不够，但缺它不行**。

### ① 事故块（结构层）——"这块根本算不出效率"

正常编辑样本应呈现几十种 indel 的谱系（Cas9 切割后随机修复）。以下模式指向实验/参照事故：

- **50/50 双峰**：一半 reads 纯 WT、一半带同一个变异 → 像杂合子材料（突变从亲本遗传）或 PCR jackpot；
- **~100% 单一变异、无 WT**：如 ref22B20 全部 6 块 100% 携带同一 28bp 缺失 → 材料本身带固定缺失，与公司参照不配套。

**解法：块级 QC 剔除**（已执行）。三规则：无 WT 行 / 非 WT 主型 ≥80% / 前两名均在 35–65% 且非 WT。877 行中标记剔除 350 行（新表备注列 `QC剔除(...)`，可追溯不物理删除；清单 `results/qc_excluded_0918.csv`）。剔除率最高：USR-6883 (82/94)、6137 (55/80)、6444 (33/48)、7342 (19/26)。

### ② 批次效应（标签层）——"块看着正常，但整批偏高/偏低"

剔除解决不了它，因为单个块看不出毛病，只有跨批次同 guide 对比才暴露。直接证据（guide `GGCGTTAGATTGACAGAAGA`，LG05.2725）：

| 批次 | n | indel 均值 |
|---|---|---|
| 旧 USR-5713 | 86 | 0.058 |
| 旧 USR-4411 | 54 | 0.045 |
| 新 USR-14333 | 26 | **0.929** |
| 新 USR-5448 | 15 | **0.322** |

**解法：锚定校正**（已验证有效，见 3.2）。

### ③ guide 身份（特征层）——"标签可能挂在错误的序列上"

- 旧表的 guide 身份来自**团队设计台账**（主表 Sheet2 位点登记表），且 25 条 guide 全部经基因组复核过——可信基准。
- 新批次的设计表**不在仓库里**（全库检索无结果），只能从 reads 反推：拼扩增子（可靠）→ 编辑热点定位 → Cas9 几何筛 NGG 候选。已用旧批次验证过反推**会出错**（如 USR-25902 ref73933gene2：缺失可延伸到切点上游 10bp 以上，几何上无法区分相距 12bp 的两个候选）。
- 风险性质：guide 填错不是噪声，是**系统性错配**——indel 标签挂在错误的 20nt 序列上入模。

**三层的分工**（为什么缺一不可）：

| | ③ guide 确认 | ② 批次校正 |
|---|---|---|
| 修的是 | 特征 X（这行是不是这条 guide） | 标签 y（不同批次的值能不能比） |
| 坏了会怎样 | 模型学"A 序列→高效率"，实际是 B 序列产生的 | 同一序列标签 0.05 和 0.93 打架 |
| 类比 | 把答案写到正确的科目名下 | 把各省考卷换算到同一满分制 |

**关键实验证据**：只加 57 行 guide 100% 确定的新数据（③ 完美），LOGO-CV 照样从 0.414 跌到 0.220——证明 ② 独立存在；锚定校正（② 修好）后仍只有 0.280——证明 ③ 独立存在。
