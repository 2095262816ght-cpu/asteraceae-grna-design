### 2.3 crisprScore 尝试与证伪（9.7 晚，4 个连环坑）

1. **CRAN 镜像未设**：Rscript 非交互模式没有默认 repo → 补 `options(repos=...)`（清华 CRAN）。
2. **TUNA 不镜像 Bioconductor 过期版本的包仓库**：TUNA 的 Bioc 3.18（R 4.3 对应版本）目录只剩文档，无 src/bin 包文件 → 逐一探测后改用**西湖大学镜像**（`mirrors.westlake.edu.cn/bioconductor`，3.18 完整）。
3. **bioconductor.org 不可达**：BiocManager 启动时要下载官方 config.yaml 校验版本，超时 → 绕过 BiocManager，直接把 repo 指向西湖镜像装包。crisprScore 1.6.0 及全部依赖安装成功。
4. **basilisk Windows 激活 bug**（最硬的一个）：crisprScore 底层用 basilisk 管理隔离 conda 环境，其激活机制是 `conda.bat activate && Rscript -e "socketConnection..."`。实测发现 `conda activate` 会替换 PATH，导致子进程 Rscript 找不到本环境 `Library/bin` 下的 DLL，退出码 309（= 0xC0000135，STATUS_DLL_NOT_FOUND），进而触发 basilisk 的连锁 bug（`object 'listener' not found`）。处理：写了进程内补丁 `env/patch_basilisk.R`，用 `assignInNamespace` 替换 basilisk.utils 的激活函数，直接按 conda 规则前置 PATH，不开子进程。**该补丁已验证有效，保留备用**。

**证伪结论**：
- crisprScore 的 DeepSpCas9 隔离环境定义为 **python 2.7 + tensorflow 1.4.1**，而 TF 在 Windows 上从未发布过 py2.7 的 pip 包（pip 报 "from versions: none"）——Windows 原生无解；
- 查阅 crisprScore 最新 master 源码的导出列表，**该包任何版本都没有 CRISPRon 函数**（详案"一个包同时给两个模型"的前提不成立）。

→ 触发详案降级链，执行**降级方案 1**：genet（DeepSpCas9）+ CRISPRon 官方仓库。

### 2.4 CRISPRon 官方仓库部署（9.7 晚，WSL）

CRISPRon 官方实现是 bash + ViennaRNA(RNAfold) + TF2 的 Linux 工具链，Windows 原生不可行 → 启用机器上已有的 **WSL Ubuntu-22.04**：

1. WSL 内装 Miniconda（清华镜像），配置 `.condarc` 镜像映射；
2. 建 `crispron` 环境：python 3.10 + tensorflow 2.14 + viennarna 2.6.4 + biopython/pandas/sklearn（官方 environment.yml 里的 igv/blat/repeatmasker 等是作者做基因组注释用的，打分用不到，做了精简）；
3. 从 rth.dk 下载 CRISPRoff 组件，按官方 README 组装（`CRISPRspec_CRISPRoff_pipeline.py` → bin/，`energy_dics.pkl` → data/model/）；
4. 跑官方测试 `test.sh`：**341 条测试序列全部出分，与参考结果最大偏差 0.01**（纯 TF 版本尾数噪声，能量参数部分完全一致）。首次 diff 失败只是 Windows git 把参考文件检出成 CRLF 所致，已统一换行符。

过程中处理的两个工程坑：
- **wsl.exe 会把多行 `bash -c` 字符串拆散成碎片执行**（日志错乱排查了半天）→ 纪律：WSL 命令一律写成脚本文件再执行（`env/setup_crispron_wsl.sh`）；
- Git Bash 会把 `/mnt/d/...` 路径误转成 Windows 路径 → 传 WSL 的路径加 `MSYS_NO_PATHCONV=1`。
