## 一、方向结论（9月7日核实）

**莴苣 T2T 表观组学方向 → 放弃主线地位**，原因（已联网核实）：

1. CRA014517 里**没有** CENH3 / H3K4me3 / H3K27me3 / H3K9me2 的 ChIP-seq 原始数据（1.44 TB 数据全是 HiFi/ONT/Hi-C/RNA-seq/Iso-seq），NCBI SRA 也搜不到，只能邮件向郭立团队索取，时间不可控；
2. LettuceGDB 网站目前被 ICP 拦截，整站不可用；
3. 没有 ChIP-seq 峰/信号数据就没有表观组训练标签，该方向无法成立为计算项目。

**主线 → Chen2022 方向（即融合版 v2 的技术内核）**：

> 公开预训练模型（DeepSpCas9 + CRISPRon）→ 自有橡胶草 Hi-TOM 实测数据做 Stacking 集成（复刻 Chen2022 ensemble_ridge 思路）→ 包装成"菊科通用 gRNA 设计工具"demo，莴苣 T2T 基因组做演示对象。

**零成本对冲**：给郭立团队发一封邮件索取 ChIP-seq 数据（10 分钟），不作为任何环节的依赖；若意外拿到，作为报告的"后续工作"素材。

## 二、技术路线（砍掉所有可选支线）

```
DeepSpCas9 打分 ─┐
CRISPRon 打分 ───┼→ 特征矩阵 → 岭回归元模型(Stacking) → 自有Hi-TOM数据训练/验证
(可选)DeepHF ────┘                                        │
                                                          ↓
莴苣T2T基因组扫描候选gRNA → 模型打分 → Cas-OFFinder脱靶过滤 → Streamlit demo
```

**默认走 Stacking，不走微调**。理由：Stacking 只需几十条自有数据、训练是秒级的岭回归、无 GPU/环境风险、有 Chen2022 论文背书（12 个独立数据集中 10 个优于最强单算法）。微调只有在数据盘点确认 ≥几百条且时间富余时才作为加分项尝试。

**明确砍掉**（相对融合版 v2）：
- ❌ 多组学加分项全线（ATAC 特征、SeiPlant 族级模型）——数据链路已断，且占时间；
- ❌ CRISPR-AIDIT / CRISPR_HNN 加试——两个模型够做 Stacking，多一个模型多一份环境风险；
- ❌ 数据扩充三途径（公开数据混合/伪标注/噪声扰动）——除非指标不达标才启用第①条；
- ❌ BLAST 同源映射到向日葵等第二物种——报告里写"框架支持"即可，不实际做；
- ❌ 湿实验闭环——写进报告"后续计划"；
- ❌ 原版 DeepSpCas9 TF1.x 代码复现——直接用 crisprScore / genet 封装。

## 三、27 天排期（每天 3 小时）

### 阶段 0：数据盘点 + 环境（9.7–9.9，约 9h）
| 天 | 任务 |
|---|---|
| 9.7 | 发 ChIP-seq 索取邮件（10min）；盘点自有 Hi-TOM 数据：条数、序列、坐标、PAM、批次、效率值是否齐全 |
| 9.8 | Hi-TOM 数据清洗成统一表格（30bp 上下文+PAM+归一化效率）；画批次分布图 |
| 9.9 | conda 建环境，装 crisprScore 或 genet，跑通一个示例打分 |

🔶 **决策点 D1（9.8 晚）**：自有数据条数定路线——
- ≥300 条：Stacking 为主，可加试微调；
- 30–299 条：纯 Stacking（预期大多数情况）；
- <30 条：Stacking 仍可做，但指标改用留一交叉验证，报告侧重"工具+方法"而非模型性能。
- 数据拿不到/质量太差：🔴 立即找老师确认数据在哪，这是全项目最大风险。

### 阶段 1：预训练模型打分 + 迁移可行性（9.10–9.12，约 9h）
| 天 | 任务 |
|---|---|
| 9.10 | DeepSpCas9 对全部自有 gRNA 打分 |
| 9.11 | CRISPRon 打分；下载 DeepSpCas9 Table S1（12,832 条）备用 |
| 9.12 | 算两个模型打分 vs 实测效率的 Spearman ρ，出结论 |

🔶 **决策点 D2（9.12）**：参照 Chen2022 结论，ρ 在 0.3–0.5 即正常（单模型水平），Stacking 后预期 0.5+。若 ρ < 0.2：检查坐标/PAM 取向是否搞反（最常见 bug），修正后仍 <0.2 则在报告中如实呈现并侧重工具价值。

### 阶段 2：Stacking 模型 + 评估（9.13–9.19，约 21h）
- 9.13–9.14：特征矩阵组装（2–3 个模型打分 + GC 含量等简单序列特征）；
- 9.15–9.17：岭回归元模型训练，**按基因分组划分训练/测试集**（防数据泄漏，评审会查）；留一基因交叉验证；
- 9.18–9.19：对比单模型 vs 集成模型的 ρ 和 AUC，出结果表格和图；**达标线：测试集 ρ ≥ 0.5**。不达标→启用公开数据加权混合（仅此一条扩充途径，1 天上限）。

### 阶段 3：莴苣工具化 + demo（9.20–9.26，约 21h，可与阶段 2 最后几天交叠）
- 9.20–9.21：下载莴苣 T2T 基因组（Figshare 链接，浏览器打开）+ 注释；
- 9.22–9.23：写扫描脚本：基因区（启动子+外显子）枚举 NGG PAM 上游 20nt → 模型打分；
- 9.24：Cas-OFFinder 脱靶过滤（本地跑）；
- 9.25–9.26：Streamlit demo：输入基因名/序列 → 输出排序后的 gRNA 推荐表 + 脱靶数。1–2 天出活，不做全栈。

## 四、答辩叙事五要点（沿用融合版 v2）

1. 菊科（全球重要蔬菜/经济作物）**没有**专用 gRNA 设计工具，现成工具全为人/鼠训练；
2. 自有橡胶草 Hi-TOM 高通量实测数据是稀缺标签资源；
3. 方法复刻并有据：Chen2022 证明 Stacking 集成优于一切单算法，且我们证明了它在植物体系有效；
4. 橡胶草↔莴苣同属菊科菊苣族，工具天然覆盖族内物种；
5. 交付可运行的在线 demo，不是纸面模型。

⚠️ 表述纪律：一律写"菊科菊苣族蒲公英属"，不写"莴苣属下同种"。
